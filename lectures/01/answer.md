## 演習

### 一般的な用語への質問

ベースモデルの重みを固定し、少数の追加パラメータを学習することで、追加学習に必要なメモリなどを抑える技術という説明が返った。

### 講座に固有の質問

質問：`AIE2026の講座の宿題にある「3レベル」とは何ですか？`

`gemini-3.5-flash-lite` の1回目は、講座名の意味を推測したうえで、一般的な「基礎・入門」「応用・実践」「発展・挑戦」という3段階の難易度を説明した。
最後に教材や問題文の確認を促したが、講座で定めた3レベルの名称と完了条件を正確には答えなかった。
入力トークン数は **21**、出力トークン数は **426** だった。

`data/glossary.json` の `homework-levels` にある正しい意味は、次のとおり。

- 基礎：講義内容の確認
- 実装：自分でコードを書く
- 発展：調査や試行
- どれか1つに取り組めば、その回の宿題は完了。原則として採点はしない。

モデルの回答は、3段階に分かれるという点は似ていたが、「実装」という名称と「どれか1つで完了」という重要なルールが抜けていた。
推測であることや資料を確認すべきことには触れていても、その説明だけでは実際に何を提出すればよいか判断できない。
説明が詳しくても、講座固有のルールを正しく答えているとは限らなかった。

## 宿題

### 取り組んだレベル

**基礎**：モデルを変え、同じ質問を各モデルで3回ずつ実行し、回答の違いを比較した。

### やったこと

演習と同じ「宿題の3レベル」の質問を、以下の2モデルでそれぞれ3回実行した。
演習で使った `gemini-3.5-flash-lite` の1回目も、この比較の1件に含めた。

- `gemini-3.5-flash-lite`
- `gemini-3.1-flash-lite`

変更したのは環境変数 `AIE_MODEL` のみ。temperatureやseedは指定していない。
各回を独立したプロセスで実行し、会話履歴や講座資料はモデルに渡していない。

### 気づき・疑問

- 同じモデル・同じ質問でも、レベルの呼び名、説明例、確認の促し方、回答の長さが変わった。
- 今回の3回では、`gemini-3.5-flash-lite` は難易度という1つの解釈を中心に説明し、`gemini-3.1-flash-lite` は複数の解釈を並べる傾向があった。出力トークン数も、それぞれ426〜525、634〜667で異なった。
- どちらも推測や一般論である旨を添える場面があった。ただし、丁寧で長い説明が返ることと、講座のルールを知っていることは別だった。
- 講座固有の質問には、正しい資料をモデルに渡すか、用語集を検索する仕組みが必要だと考えた。資料を渡した場合の効果は、今回の実験では確認していない。
- 各モデル3回だけの比較なので、この結果からモデル全体の優劣は判断できない。

### 再実行用コマンド

APIキーを環境変数に設定するか、ローカルのGit管理対象外の `.env` に設定したうえで、リポジトリのルートから実行する。
以下は `.env` を利用する場合の例。

```bash
uv run --env-file .env python -m app.ask "LoRAとは何ですか？"

for model in gemini-3.5-flash-lite gemini-3.1-flash-lite; do
  for trial in 1 2 3; do
    AIE_MODEL="$model" uv run --env-file .env python -m app.ask "AIE2026の講座の宿題にある「3レベル」とは何ですか？"
  done
done
```

同じコマンドでも、再実行時の回答やトークン数が今回の記録と一致するとは限らない。
